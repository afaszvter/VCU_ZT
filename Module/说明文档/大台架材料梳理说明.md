# 大台架材料梳理说明

## 1. 目标

本说明用于支撑两项工作：

1. 根据现有材料梳理模块间通信关系，形成 `DBC` 编写基线。
2. 根据线束/接口/协议材料搭建 `I/O Simulink` 模型骨架。

当前材料里同时存在：

- 整车级需求文档
- VCU 硬件手册
- VCU 线束接口梳理
- 整车 CAN 矩阵
- 电机/PDU/辅驱协议
- 三通阀协议
- 制动电阻协议与规格书
- 原理图图纸

这些文件并不完全一致，所以第一步不是直接写 DBC，而是先建立“基线版本”和“主数据来源”。

---

## 2. 建议的主数据来源

### 2.1 优先级结论

建议按下面顺序作为后续工作的“主来源”：

1. `VCU接口梳理 - 20260602.xlsx`
   用于新 VCU 管脚、I/O 类型、线束映射。
2. `整车CAN20260423.xls`
   用于最新整车 CAN/动力 CAN 报文矩阵。

   用于系统功能、模块关系、流程解释、缺失协议补充说明。

   用于补齐设备级细节，优先使用与 `整车CAN20260423.xls` 一致的版本。

   用于最终核对线束、继电器、接触器、供电与总线拓扑。

### 2.3 已发现冲突

1. `ZT_SPV_CAN通讯协议_V1.1——电池电机.xls` 和 `开关磁阻电机MP2505_深蓝动力矿卡四合一通讯协议.xls` 中部分动力 CAN 报文 ID 不一致。
   例如驱动电机控制报文：
   - `ZT_SPV` 中 `VCU_DrvMCU1 = 0x0C31F0D0`
   - `整车CAN20260423` / `开关磁阻专用协议` 中对应为 `VCU2MCU2 = 0x0C31F1D0`

2. 三通阀存在两套协议来源：
   - `三通电磁阀2733523...xls`：250 kbps，ID 为 `0x0cfd6720 / 0x18FD20B0`
   - `Φ25 V560424A15三通比例阀can协议.xlsx`：500 kbps，ID 为 `0x18FF25EF / 0x18FF243B`
   其中 `整车CAN20260423.xls` 已采用后者，因此建议以后者为准。

3. `VCU接口梳理.xlsx` 是旧版接口表，没有新 VCU 管脚分配；`VCU接口梳理 - 20260602.xlsx` 已补充新 VCU 管脚，应以后者为准。

## 4. 目前能确定的模块和接口

## 4.1 控制器与节点

### 整车 CAN（建议命名 CANA）

- `VCU`
- `BMS`
- `OBC`
- `TMS`
- `ICU`
- `BRS/BRC` 制动电阻控制器
- 可能还有未使用的永磁同步 E3/E4、开关磁阻 18/19，但当前需求文档说明它们未使用

### 动力 CAN（建议命名 CANB）

- `VCU`
- `开关磁阻多合一 / MCU`
- `PDU / HVC`
- `DCDC`
- `DCAC(油泵)`
- `DCAC(气泵)`
- `三通比例阀 TWV`
- 主驱/辅驱电机控制器

### 调试 CAN（建议命名 CANC）

- 当前主要作为调试口，接口表中只有 VCU `CAN2H/CAN2L`

## 4.3 传感器/执行器硬件特征

### 电子油门踏板

来自 `b5f20a1102ca53c27e7d94f44ab56e32.jpg`：

- 双路供电、双路地、双路信号输出
- 典型 6 针
- 5V 供电
- 两路输出 `Vs1 / Vs2`
- 适合建成 `Pedal1Raw`、`Pedal2Raw`、`PedalPlausibility` 三块

### OKT7 温度变送器

来自 `OKT7温度变送器.pdf`：

- 输出型式可能为 `4...20mA`、`0...5V`、`0...10V`
- 供电 `12...30Vdc`
- 量程示例 `0...100°C`

结论：

- 必须先确认现场型号到底是电流型还是电压型。
- 若是 `4...20mA`，VCU 不能直接按普通 0~5V 模拟量处理，需确认前端是否有采样电阻或调理板。

### 制动电阻系统

来自 `制动电阻系统规格书（风冷100Kw）V7(1).pdf`：

- 控制电压 `DC24V`
- 高压输入/输出 `400~800VDC`
- 额定功率 `100kW`
- 与整车通讯 CAN 口：`CANAH / CANAL`
- 还带风扇控制、风扇故障、温度采集接口

结论：

- 你当前做 DBC 时，优先处理其 CAN 通信部分。
- 做 I/O 模型时，需要考虑它除了 CAN 以外还有接触器状态和可能的风扇/温度相关联动。

## 6. 做 DBC 时的建议

## 6.1 先分两个 DBC

不要先做一个大而全的 DBC，建议至少拆成两个：

1. `bench_vehicle_can.dbc`
   对应整车 CANA
2. `bench_power_can.dbc`
   对应动力 CANB

调试 CANC 可以先不建，除非现场有明确报文。

## 6.2 DBC 的编写顺序

### 第一步：先建节点

#### 整车 CANA 节点

- `VCU`
- `BMS`
- `OBC`
- `TMS`
- `ICU`
- `BRS`

#### 动力 CANB 节点

- `VCU`
- `PDU`
- `HVC`
- `MCU_Oil`
- `MCU_Drv`
- `DCDC`
- `ACU_OilPump`
- `ACU_AirPump`
- `TWV`

### 第二步：只录入消息头

先把每个报文的：

- 报文名
- ID
- DLC
- 周期
- 发送节点

全部建完，不要一边建报文一边抠每个 bit。

### 第三步：补信号

优先补下面几类信号：

1. 状态机必需信号
   如上下电、继电器状态、Ready、故障等级、唤醒
2. 控制闭环必需信号
   如扭矩、转速、风扇档位、功率请求
3. 监控显示信号
   如温度、电压、电流、SOC、故障码

### 第四步：补枚举和无效值

尤其要补：

- 故障等级
- 工作模式
- 继电器状态
- 档位/控制模式
- 心跳计数

## 6.3 需要优先确认的冲突项

1. 动力电机到底采用：
   - `开关磁阻专用协议`
   - 还是 `ZT_SPV` 中那套 ID

2. 三通阀现场实物到底是：
   - `Φ25 V560424A15`
   - 还是 `2733523`

3. 制动电阻接触器状态是否由高压配电柜报文提供，还是由别的控制器提供。

4. 永磁同步与开关磁阻是否同时保留在 DBC 内，还是只保留当前台架用的一套。

## 7. 做 Simulink I/O 模型时的建议

## 7.1 推荐模型分层

建议拆成 5 层：

1. `HAL_IO`
   物理量采集与驱动，直接对应 AI/DI/PWM/LSO/HSO/CAN 驱动
2. `IF_CAN_RX`
   各路 CAN 报文解包
3. `IF_CAN_TX`
   各路 CAN 报文打包
4. `SIG_COND`
   量纲换算、滤波、故障诊断、双通道一致性检查
5. `APP_CTRL`
   上下电、充电、冷却、驱动、附件控制逻辑

## 7.2 先搭骨架，不要先写逻辑

第一轮模型先做到：

- 所有输入口有名字
- 所有输出口有名字
- 所有 CAN 报文都有收发容器
- 所有重要信号都有 Bus/Struct 对应

不要一开始就进入状态机细节。

## 7.3 建议先建的 Simulink 子系统

1. `VCU_InputIf`
   - Key
   - Gear
   - Pedal
   - Switch
   - Temp

2. `VCU_OutputIf`
   - Pump
   - Fan1PWM
   - Fan2PWM
   - Horn
   - Relay
   - Valve outputs

3. `CANA_Rx`
   - BMS
   - OBC
   - TMS
   - BRS

4. `CANA_Tx`
   - VCU_BMS
   - VCU2ICU
   - VCU2BRS
   - VCU2TMS

5. `CANB_Rx`
   - PDU/HVC
   - MCU
   - DCDC/DCAC
   - TWV

6. `CANB_Tx`
   - VCU_PDU
   - VCU2MCU
   - VCU_DCDC1
   - Ctrl_HVC
   - VCU_ACU1
   - VCU_TWV

7. `PowerStateMgr`
   - 低压上电
   - 高压上电
   - 常规下电
   - 异常下电

8. `ChargeMgr`
   - 慢充请求
   - BMS 交互
   - OBC 唤醒

9. `CoolingMgr`
   - TMS 档位请求
   - 双风扇 PWM
   - 水泵控制

10. `ActuatorMgr`
   - 阀类
   - 喇叭
   - 缓速器

## 7.4 量纲换算建议

应把以下内容单独做成换算模块，不要散落在业务逻辑里：

- 油门双通道比例换算
- 温度变送器量程换算
- PWM 百分比与占空比换算
- CAN 物理量 `raw <-> physical` 换算
- 故障码/枚举值解释

## 8. 你接下来最应该怎么做

## 8.1 第一阶段：冻结基线

输出物：

- 一份 `协议采用清单`
- 一份 `冲突项清单`

动作：

1. 认定 `VCU接口梳理 - 20260602.xlsx` 为 I/O 基线。
2. 认定 `整车CAN20260423.xls` 为总线基线。
3. 对动力系统冲突项做一次人工确认。
4. 对三通阀型号做一次人工确认。

## 8.2 第二阶段：先做信号总表

输出物：

- `Signal List` 总表，建议列：
  - `Network`
  - `Node`
  - `Direction`
  - `Message`
  - `ID`
  - `Signal`
  - `Unit`
  - `Scale`
  - `Offset`
  - `Type`
  - `Source File`
  - `Status`

动作：

1. 先录整车 CAN。
2. 再录动力 CAN。
3. 再录物理 I/O。

## 8.3 第三阶段：先出 DBC 框架

输出物：

- `bench_vehicle_can.dbc`
- `bench_power_can.dbc`

动作：

1. 先建节点和报文头。
2. 再补关键控制信号。
3. 最后补诊断和显示信号。

## 8.4 第四阶段：搭 Simulink I/O 骨架

输出物：

- `bench_io_top.slx`
- `cana_if.slx`
- `canb_if.slx`
- `io_hal.slx`

动作：

1. 先搭端口和总线。
2. 再接报文打包解包。

## 12. 当前 Simulink 工程理解

本节基于当前 `Module/MainModel/ZT_VehCtrl_18B.slx`、`VCU_INIT.m` 和 `整车CAN20260630_MB分配.xlsx` 梳理，目的是把“已经搭好的 CAN 收发框架”继续落到控制逻辑实现。

当前模型不是空白工程，顶层已经具备以下结构：

| 顶层模块 | 当前作用 | 后续处理建议 |
| --- | --- | --- |
| `Init` | CAN MB 初始化，已包含 CAN0/CAN1 接收报文初始化块 | 保留，按当前 MB 表核对所有输入报文是否已初始化 |
| `SigIn` | CAN/DAQ 输入信号汇总，输出 BMS、OBC、TMS、BRS、MCU、HVC、ACU、PDU、TWV、TM、ISG、DCDC、DAQ 等总线 | 作为输入接口层，后续只做解包、量纲转换、超时标志，不写业务逻辑 |
| `VehCtrl` | 业务控制层，已有能量管理、运动控制、故障处理、温控等旧结构 | 保留分层思路，但需要按本项目报文和 I/O 重新绑定信号 |
| `SigOut` | 输出打包与硬件输出 | 作为输出接口层，统一打包 CAN0/CAN1 发送报文和物理输出 |
| `Power Managment`、`Initialization & SPI timer1`、`SPI_EEPROM` | 电源、SPI、EEPROM、底层初始化相关 | 不作为本轮控制逻辑改动重点，除非低压电源时序需要补充 |

`VehCtrl` 内已经存在的主要业务子系统如下：

| 子系统路径 | 当前含义 | 本项目中的复用方式 |
| --- | --- | --- |
| `VehCtrl/EnergyManage1` | 高压/能量状态管理，已有 Stateflow 高压上电、Ready、下电、充电等雏形 | 改造为本项目 `PowerStateMgr + ChargeMgr + DCDC/HVC/PDU/BRS 联动` |
| `VehCtrl/MontionControl/DriveControl` | 行走、制动、模式切换、电机控制 | 改造为本项目 `DriveMgr + RegenBrakeMgr + OilPumpMgr` |
| `VehCtrl/MontionControl/ValveControl` | 制动、驻车、转向、阀类输出 | 改造为附件阀、驻车释放阀、上装/支腿/四轮转向/斜行阀控制 |
| `VehCtrl/TempertureControl` | 温控分级和风扇/水泵控制 | 改造为电机/电控/电池/TMS/三通阀统一冷却控制 |
| `VehCtrl/FaultProc` | 通信超时、丢包、故障汇总 | 扩展为 CAN0/CAN1 报文超时、故障等级仲裁、降级/禁行/紧急下电 |
| `VehCtrl/SpdCalc` | 车速、扭矩、功率估算 | 结合当前单驱动电机反馈重新简化，避免保留旧四轮驱动假设 |

结论：后续不要把控制逻辑写进 CAN 解包/打包块里，而应继续保持三层结构：

1. `SigIn`：输入解包、物理量换算、有效性判断、超时标志。
2. `VehCtrl`：低压、高压、行走、制动、冷却、附件、故障状态机。
3. `SigOut`：CAN 发送报文打包和 HSO/LSO/PWM 输出。

### 14.1 数据流约束

1. `SigIn` 输出的是“已解包并带有效性标志”的总线，例如 `BMS.Bus`、`MCU2.Bus`、`HVC.Bus`、`BRS.Bus`。

4. `SigOut` 只负责把命令总线打包为 CAN 报文或物理输出，不再做状态判断。
5. 所有生命计数、报文超时、默认值要集中管理，避免分散在不同子系统。

## 15. 分功能需求与实现方案

### 15.1 低压管理 `LvPowerMgr`

#### 输入

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| `KeyOn` | 物理输入 | KEY ON 或充电继电器连接 |
| `KeyStart` | 物理输入 | 启动请求 |
| `ChgWake` | HVC 或 OBC/BMS | 慢充唤醒 |
| `HvState` | `PowerStateMgr` | 判断是否允许断低压 |

#### 输出

| 输出 | 去向 | 说明 |
| --- | --- | --- |
| `VCU_MainRelayCmd` | `LSO01` | VCU 主继电器 |
| `ObcWakeEnable` | `HSO05` | 慢充时 OBC 唤醒 |
| `LvReady` | 内部状态 | 低压系统已保持 |

#### 状态机

| 状态 | 进入条件 | 输出 | 退出条件 |
| --- | --- | --- | --- |
| `LV_OFF` | 无 KeyOn 且无充电唤醒 | 主继电器断开 | `KeyOn=1` 或 `ChgWake=1` |
| `LV_WAKE` | 唤醒成立 | 主继电器闭合，初始化计时 | 初始化完成 |
| `LV_ON` | 初始化完成 | 允许高压/充电状态机运行 | KeyOff 且无充电 |
| `LV_DELAY_OFF` | KeyOff 后 | 保持主继电器，等待 CAN 下电完成 | 高压已下电且延时到 |

实现时把延迟断电时间做成标定量，例如 `K_LvOffDelay_ms`。如果高压状态未退出，不允许直接断开 `LSO01`。

### 15.2 高压电管理 `PowerStateMgr`

#### 高压允许条件

高压上电前必须同时满足：

1. `LvReady=1`。
2. `BMS_ReadySt` 不为 Error。
3. `BMS_SelfCheckStatus=1`。
4. `BMS_AlarmLevel` 小于禁止上高压阈值，建议 0/1 允许，2 降额，3/4 禁止。
5. `HighVoltLoopLockStatus` 有效且互锁正常。
6. `PositiveInsulationResistance`、`NegativeInsulationResistance` 不低于标定阈值。
7. BMS、HVC、PDU、MCU 关键报文未超时。
8. 驱动电机目标扭矩为 0，档位为 N 或油门无效区。

#### 输出命令

| 命令 | 报文/硬件 | 说明 |
| --- | --- | --- |
| `VCU_PowerOnReq` | `VCU_BMS` | 请求 BMS 上高压 |
| `VCU_UrgencyCutOffPowerReq` | `VCU_BMS` | 紧急下高压 |
| `EDrv1_PowOnCmd`、`EDrv2_PowOnCmd` | `Ctrl_HVC` | 电驱支路上电 |
| `VCU_ShrRlyCtl`、`VCU_DCCpstRlyCtl` 等 | `VCU_PDU` | PDU 支路继电器 |
| `VCU_DCDC1_En` | `VCU_DCDC1` | DCDC 使能 |
| `OnOffCmd` | `VCU2BRS` | 制动电阻上下电 |

#### 状态机

| 状态 | 关键动作 | 转移条件 |
| --- | --- | --- |
| `HV_OFF` | 所有高压相关输出为 0，电机使能 0，BRS 下电 | 收到运行或充电高压请求 |
| `BMS_REQ_ON` | `VCU_PowerOnReq=1`，紧急下电为 0 | BMS 进入预充 |
| `PRECHARGE` | 保持 BMS 上电请求，电机命令仍为 0 | `BMS_PrechargeStatus=2` 且主正/主负状态闭合 |
| `PDU_HVC_ON` | 允许 HVC/PDU 电驱支路上电 | `MotDrv*_PowOnSt=1` 或对应接触器闭合 |
| `HV_READY` | DCDC 可使能，允许驱动/冷却/附件运行 | KeyOff、充电结束、严重故障 |
| `NORMAL_DOWN` | 先清扭矩和电机使能，再关 DCDC/BRS/PDU/BMS | 所有反馈断开或延时到 |
| `EMERGENCY_DOWN` | 立即清扭矩、禁用电机、发紧急下电 | 故障锁存，需要人工复位 |

制动电阻的时序必须单独处理：只有车辆高压配电柜中制动电阻接触器已闭合后，才允许 `VCU2BRS.OnOffCmd=1`；下高压时先发 `OnOffCmd=0`，再断开高压配电柜中的制动电阻接触器。

### 15.3 充电管理 `ChargeMgr`

#### 输入

- `BMS_ChargeMode`
- `BMS_ChargeStatus`
- `BMS_PrechargeStatus`
- `OBC_StartSt`
- `OBC_ComSt`
- `OBC_HwFault`
- `OBC_Voltage`
- `OBC_Current`
- `HVC_ChgWakeUpVol`
- 充电使能开关

#### 输出

- `ObcWakeEnable`
- `VCU_PowerOnReq`
- `VCU_DCDC1_En`
- 仪表充电状态 `VCU_VehACharge_b`、`VCU_VehDCharge_b`

#### 实现原则

1. 慢充唤醒时，低压先保持，再允许 BMS/OBC 通信。
2. BMS 确认为交流充电模式后，由高压状态机完成 BMS 高压闭合。
3. 行驶、快充、慢充状态均需要 DCDC 时，只要多合一控制器主正完成上高压，即可使能 DCDC。
4. OBC 硬件故障、通信故障或 BMS 充电故障时，退出充电请求并进入故障显示。
5. 充电结束后，按正常下电流程释放高压和低压保持。

### 15.4 行走控制 `DriveMgr`

#### 输入

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| `Pedal1Raw`、`Pedal2Raw` | AI | 双路油门电压 |
| `GearD`、`GearR` | DI | D/R 档，当前接口表中为低有效 |
| `HvReady` | `PowerStateMgr` | 高压 Ready |
| `FaultBus` | `FaultMgr` | 禁行、降扭、紧急下电 |
| `BMS` | CAN0 | SOC、电压、电流、报警、充放电能力 |
| `MCU2` | CAN1 | 驱动电机状态、转速、转矩、故障、限功率 |
| `HVC/PDU` | CAN1 | 电驱支路上电状态 |

#### 油门处理

`VCU_INIT.m` 中已有油门标定初值：

| 参数 | 当前值 |
| --- | --- |
| `PadleSignal1_min` | 0.75 V |
| `PadleSignal1_max` | 3.84 V |
| `PadleSignal2_min` | 0.375 V |
| `PadleSignal2_max` | 1.92 V |
| `PadleValid` | 0.05 |

建议建立 `PedalProc` 子系统：

1. 对两路电压分别做范围检查，低于最小值或高于最大值均置故障。
2. 分别归一化到 0-100%。
3. 检查双路一致性。由于第二路量程约为第一路一半，应先归一化后比较，两路差值超过 `PadleValid` 判定油门不可信。
4. 油门不可信时，目标扭矩强制为 0，并上报 `VCU_AccPedSt_pct` 和故障位。
5. 加入死区和斜率限制，避免目标扭矩阶跃。

#### 档位仲裁

| D 输入 | R 输入 | 档位结果 |
| --- | --- | --- |
| 有效 | 无效 | D |
| 无效 | 有效 | R |
| 无效 | 无效 | N |
| 有效 | 有效 | N + 档位故障 |

档位切换只允许在油门为 0 且车速/电机转速低于阈值时生效。运行中换向时先进入 N，目标扭矩清零，待速度满足条件后再进入目标档位。

#### 驱动电机输出

开关磁阻驱动电机优先使用 `VCU2MCU2`：

| 信号 | 生成逻辑 |
| --- | --- |
| `VCU2DrvMotor_En` | `HvReady=1`、无禁行故障、档位有效 |
| `VCU2DrvMotor_WorkMode` | D 档正转电动，R 档反转电动；再生制动时切到对应发电模式 |
| `VCU2DrvMotor_CtrlMode` | 行走优先扭矩控制；需要恒速时再切速度控制 |
| `VCU2DrvMotor_BusCurLimit` | 取 BMS 允许放电能力、MCU 限功率、HVC 状态的最小约束 |
| `VCU2DrvMotor_TarTrq` | 油门开度查表后，经限功率、故障降额、斜率限制 |
| `VCU2DrvMotor_TarSpd` | 扭矩模式下置 0 或保留值；速度模式下由目标车速换算 |
| `VCU2DrvMotor_RegenVoltLimit` | 按电池最高允许回充电压或协议默认值 |
| `VCU2DrvMotor_CtrlBusCounter` | 10 ms 计数循环 |

如果现场需要同时保留永磁同步 TM/ISG，则同一行走请求还要映射到 `TM HCU Command` 和 `ISG HCU Command`，但不能与 `VCU2MCU2` 重复驱动同一执行对象。当前阶段建议先确认实际电机系统，只启用一套执行链。

### 15.5 油泵/液压泵站控制 `OilPumpMgr`

油泵电机优先使用 `VCU2MCU1`。

| 场景 | 目标 |
| --- | --- |
| 转向、制动、上装、支腿等液压需求有效 | 油泵使能，按需求给目标转速 |
| 高压 Ready 但无液压需求 | 油泵待机或低速保压，具体阈值待现场标定 |
| 油泵 MCU 故障、HVC 支路未上电 | 油泵禁用，并禁止依赖液压的附件动作 |

输出信号包括 `VCU2OilMotor_En`、`VCU2OilMotor_WorkMode`、`VCU2OilMotor_CtrlMode`、`VCU2OilMotor_TarSpd`、`VCU2OilMotor_TarTrq`。液压泵站建议优先速度控制，转矩只作为保护或限矩使用。

### 15.6 制动与再生制动 `RegenBrakeMgr`

需求文档明确：常规制动由驾驶员通过其他部件实现，VCU 主要负责再生制动、制动电阻和缓速器低压控制预留。

#### 再生制动触发

当前可实现的第一版逻辑：

1. 油门开度小于死区。
2. 车速或驱动电机转速大于标定阈值。
3. 高压 Ready。
4. 驱动电机无禁止发电故障。
5. BMS 允许回充，或制动电阻可用。

#### 功率分配

再生制动总功率上限为：

`P_regen_limit = P_bms_charge_allow + P_brs_available`

其中 `P_brs_available` 来自 `BRS2VCU2.AvailableMaxPower`，并受 `BRS2VCU1.FaultLevel`、`BrakeResistorTemp`、`ControllerTemp` 约束。

| 条件 | 控制策略 |
| --- | --- |
| BMS 允许回充，BRS 不需要 | 再生功率限制在 BMS 允许值内，`PowerReq=0` |
| BMS 允许值不足且 BRS 可用 | 超出 BMS 允许部分分配给 BRS，`VCU2BRS.PowerReq` 请求泄放 |
| BRS 故障或不可用 | 再生功率只按 BMS 允许值，超出部分不再请求电机制动 |
| BMS 禁止回充且 BRS 可用 | 只允许不超过 BRS 可用功率的再生制动 |
| BMS 禁止回充且 BRS 不可用 | 再生制动目标为 0，仅保留常规制动 |

#### 输出

| 输出 | 去向 | 说明 |
| --- | --- | --- |
| `VCU2DrvMotor_WorkMode` | `VCU2MCU2` | 按行驶方向切到发电模式 |
| `VCU2DrvMotor_TarTrq` | `VCU2MCU2` | 负向或反向制动扭矩，按协议符号定义实现 |
| `PowerReq` | `VCU2BRS` | 请求制动电阻消耗功率 |
| `MaxChargePowerLimit` | `VCU2BRS` | 通知制动电阻当前最大回充/限制功率 |
| `OnOffCmd` | `VCU2BRS` | 制动电阻上下电 |
| `RetarderCmd` | `HSO10` | 缓速器控制预留 |

缓速器与常规制动的协同在需求文档中仍未完全冻结，第一版模型建议只预留 `RetarderCmd` 输出和 `RetarderEnable` 标定开关，不直接参与再生制动闭环。

### 15.7 冷却控制 `CoolingMgr`

#### 输入

- `TMS_FanSpeedLvl_num`
- `Statistic_TemperatureHTMax`
- `Statistic_TemperatureLTMax`
- `PDU_Temp`
- `Out_Temp`
- `In_Temp`
- `OilMotorTemp*`
- `OilMotorMCUTemp*`
- `DrvMotorTemp*`
- `DrvMotorMCUTemp*`
- `TWV1_P_RealSta`
- OKT7 温度模拟量或预留温度输入

#### 输出

| 输出 | 去向 |
| --- | --- |
| `WaterPumpCmd` | `LSO06` |
| `Fan1PWM` | `HSO08` |
| `Fan2PWM` | `HSO14` |
| `VCU_FanSpeedLvl_num` | `VCU2TMS响应` |
| `VCU_TWV1_P_PosSet` | `VCU_TWV` |
| `VCU_TWV1_P_MoveEnable` | `VCU_TWV` |
| `VCU_CoolSysFltIdc_b`、`VCU_CoolFanWrkIdc_b` | `VCU2ICUInfor1` |

#### 控制策略

1. 水泵在 `HV_READY`、充电、任一温度超过一级阈值时开启。
2. 风扇 PWM 取 TMS 请求档位和本地温度请求的最大值。
3. 本地温度请求采用带回差的分级控制，至少包含 0%、30%、60%、100% 四档。
4. 三通阀位置按电池冷却和电机冷却需求分配，第一版可用简单规则：
   - 电池温度高优先电池回路；
   - 电机/电控温度高优先电机回路；
   - 两者都高时置中或按标定比例；
   - 三通阀故障时保持安全默认开度。
5. TMS 请求超时后，不再完全信任 `TMS_FanSpeedLvl_num`，转为本地温度控制。

### 15.8 附件控制 `AccessoryMgr`

附件控制按开关直接驱动为主，但必须叠加系统状态和故障条件。

| 输入 | 输出 | 建议允许条件 |
| --- | --- | --- |
| 上装加载开关 | 上装加载阀 `LSO07` | 低压 Ready，油泵可用 |
| 支腿加载开关 | 支腿加载阀 `LSO08` | 低压 Ready，油泵可用，车速为 0 |
| 驻车解除开关 | 驻车解除阀 `LSO10` | 高压 Ready 或液压压力可用，无驻车低压报警 |
| 四轮转向开关 | 四轮转向阀 `LSO12` | 车速低于阈值，转向系统无故障 |
| 斜行开关 | 斜行电磁阀 `LSO13` | 车速低于阈值，四轮转向条件满足 |

### 15.9 故障处理 `FaultMgr`

故障处理要作为所有控制模块的前置输入，不建议只做显示。

#### 通信超时

按报文周期配置超时时间：

| 周期 | 建议超时 |
| --- | --- |
| 10 ms | 100 ms |
| 50 ms | 300 ms |
| 100 ms | 500 ms |
| 300/500 ms | 1500 ms |
| 1000 ms | 3000 ms |

每个输入报文生成 `MsgValid` 和 `MsgTimeout`。关键报文包括 BMS_Information 2、BMS_Relay Status、HVC4_RlySt、MCU2Msg1/2、DCDC1_2、BRS2VCU1/2、TMS2VCU、TWV。

#### 故障等级仲裁

| 等级 | 行为 |
| --- | --- |
| 0 | 正常运行 |
| 1 | 仪表报警，控制不降级 |
| 2 | 降额运行，限制驱动扭矩、限制再生功率 |
| 3 | 禁止行走，清扭矩，保持必要冷却 |
| 4 | 紧急下电，进入 `EMERGENCY_DOWN` |

故障来源包括 BMS 报警等级、DCDC 故障等级、HVC 故障等级、MCU 故障等级、BRS 故障等级、三通阀故障、油门双通道故障、档位互斥故障、关键报文超时。

## 16. 建模实施顺序

建议按下面顺序搭建，不要先从复杂行走逻辑开始。

### 16.1 第一轮：接口冻结

1. 在 `SigIn` 中确认 CAN0/CAN1 所有活跃输入报文已经解包到总线。
2. 在 `SigOut` 中确认所有活跃输出报文都有命令入口。
3. 把 `VCU_INIT.m` 中的油门标定、阈值、故障等级枚举补全。
4. 建立 `MsgValid`、`MsgTimeout`、`LifeCounter` 统一规则。

完成标准：模型中能看到所有报文信号，但控制输出仍可保持默认值。

### 16.2 第二轮：低压 + 高压

1. 搭 `LvPowerMgr`。
2. 搭 `PowerStateMgr`。
3. 先只驱动 `VCU_BMS`、`Ctrl_HVC`、`VCU_PDU`、`VCU_DCDC1`。
4. 用常量或 Dashboard 开关模拟 KeyOn、BMS Ready、预充完成、接触器反馈。

完成标准：能从 `LV_OFF` 走到 `HV_READY`，再按正常下电退出；故障输入能进入紧急下电。

### 16.3 第三轮：行走

1. 搭 `PedalProc` 和 `GearArbiter`。
2. 搭 `DriveTorqueReq`：油门到目标扭矩查表。
3. 搭 `DriveLimit`：BMS、MCU、故障降额。
4. 输出 `VCU2MCU2`，先固定扭矩模式。
5. 油泵 `VCU2MCU1` 单独做速度模式。

完成标准：D/R/N、油门有效/无效、故障降额、Ready 允许条件都能改变 `VCU2DrvMotor_*` 输出。

### 16.4 第四轮：再生制动 + 制动电阻

1. 搭 `RegenBrakeMgr`。
2. 引入 `BRS2VCU1/2/3` 反馈。
3. 输出 `VCU2BRS`。
4. 暂不启用缓速器闭环，仅保留输出开关和标定。

完成标准：松油门且车速大于阈值时能生成再生扭矩；BRS 可用时能请求泄放功率；BRS 故障时自动降低再生能力。

### 16.5 第五轮：冷却 + 附件

1. 搭 `CoolingMgr`，先实现水泵和风扇。
2. 再接 `VCU_TWV` 三通阀。
3. 搭 `AccessoryMgr`，先做直接开关输出，再叠加车速/Ready/故障条件。

完成标准：温度/TMS 请求能驱动 PWM 和水泵；附件开关能驱动阀类输出，并能被安全条件屏蔽。

### 16.6 第六轮：仪表与联调

1. 整理 `VCU2ICUInfor1~7`。
2. 把关键状态、档位、故障、温度、电机、电池、电压电流都填入仪表报文。
3. 用 TSMaster/FreeMaster 做总线联调。

完成标准：外部工具能看到稳定周期报文，所有状态能被仪表或监控页解释。

## 18. 当前仍需确认的工程问题

1. 当前模型中保留了旧项目的四轮驱动、增程器、RCU、RCUAuto 等逻辑。本项目如果没有这些硬件，应在 `VehCtrl` 内屏蔽或重命名，避免误输出。
2. `VCU2MCU1/2` 和 `TM/ISG HCU Command` 是否同时启用，需要根据现场实际动力系统确认。若只接开关磁阻系统，永磁同步 TM/ISG 命令应固定为安全默认值。
3. 制动电阻接触器闭合状态到底来自 HVC/PDU 哪个信号，需要和高压配电柜实物核对后再锁定。
4. 常规制动信号目前在需求中没有明确 VCU 输入。第一版再生制动只能按“松油门 + 车速/电机转速大于阈值”实现，不能声称已与制动踏板闭环协调。
5. OKT7 温度变送器输出类型未定。如果是 4-20 mA，必须确认 VCU 前端是否已有采样电阻，否则不能直接按 0-5 V AI 换算。
6. D/R 档为低有效这一点需要在 `SigIn` 里统一反相，业务层只接收逻辑有效的 `GearDValid/GearRValid`。
7. CAN0 报文表中 BMS 部分已经注释掉大量单体信息，但 `BMS_Relay Status` 在信号清单中仍作为控制关键输入使用，模型中应核对其 MB 初始化是否实际存在。
